# should i even do calib ? since already its giving good values (1.006 live data magnitude) much more smoother value even at no filter.
-> Yes need to do filter since at rest the with no calib magnitude should be same as gravity(9.7 or 9.8..) but its 1.006 this means -> its gravity + sensor error
-> so need to do calib to remove the error . but should we remove the error ? since after calib also we get some error .
-> so yes but still calib is IMP since it cant magically remove noise but it corrects -> Constant bias (offset) , Axis scale mismatch, axis misalignment.
-> So need to do Calib. 

# we will use no filter wala offset or filter wala ? 
-> if we use 100_filter in inference then need to use 100_filter wala calib, 
-> and if we use No_filter in inference then need to use NO_filter wala calib,
-> so as per inference filter we use - we need to use that same filter wala offset/bias.
-> For SF we will use no Filter thus no filter wala calib we will use (so we use using_motor No_filter wale data ka calib-offset and bias)
-> #(but i am not sure on this - since filtering does averaging and while collecting data we also did 25 read Avg.)

-> NO for differnt filters use offset/bias as per that. dont use single , since differnt filters has differnt offset/bias
-> so as per inference filter we use - we need to use that same filter wala offset/bias.


# should we do Manual data collection or using motor ?
-> use motor calib since its more better -> as we can see that the AVG Magnitude error of 2g_100filter_manually is 2e-6, and 2g_100filter_using_motor is 2e-8 (much accurate)
-> so dont use the manually collected data ka offset/bias , use only the using_motor. and furter also collect the data using motor only.

# we will use 1g or local_g in magneto ? and does it matter what g we use ? 
-> yes it matters you can use 1g in magneto or local_g - and as per that the magneto will give you offset and bias 
-> and that offset and bias will try to make the Magnitude close to that g.
-> ex- if 1g then it will try to make the (raw math calib) close to 1g
-> ex- if 0.978g then it will try to make the (raw math calib) close to 0.978g
-> 1g vs Local_g which has less noise ? -> both have exact similar noise after calib, as you can see above that.
-> ex -> 2g_0filter (at 1g and 0.98759g) both ka magnitude are closest to its g and has almost same error (2e-8 error on Avg Magnitude) (- 0.001 error on live magnitude).  which is super small.
-> also the Live Magnitude ka error is same for 1g or local_g. (error : 0.001 for all -> this also show that the Noise is much bigger then the precision we are playing in)
-> so either you use 1_g or local_g both are super precise. 
-> so the main question is does - using local_g increase accuracy of RPY -> Yes
-> for our super precise and accurary starpointing we need to go with Local_g. 
-> (for other application like drone,etc use 1g, but we want super accurate RPY we need to use local_g)


# XTRA:
if you use local_g then we need to do Auto_calib_g -> since suppose we calculated the offset and bias at x location where the local_g is xg , and if we go to y loation where the local_g is gy then we cant use that gx ka offset/bias. 
soo we need to calculate offset/bias again using the local_g of y place.
